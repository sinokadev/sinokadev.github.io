나는 요즘 엄청난 딜레마에 빠져있다.

C++만큼 성능이 좋으며, VM 언어가 아니고, C++만큼 강력하며, 파이썬만큼 문법이 이쁘고, C++만큼 생태계가 넓고, 모던 테크스럽지 않은 언어를 찾고 있다.

그런 언어는 존재하지 않는다.

러스트는 모던 테크스럽고, 문법이 이쁘지 않으며, Golang은 C++만큼 강력하지 못하고, 모던 테크스러우며, 파이썬은 VM 언어고, 자바도 VM 언어고, C는 C++만큼 강력하지 않으며, Zig도 C랑 마찬가지고, Nim은 생태계가 너무 좁다.

물론 C++도 저 모든것에 만족하지 않는다. 문법이 더럽다.

거의 모든 언어들이 이걸 못한다.

1. 하위 호환을 잘 지킨다.
2. 기능들을 자주 Deprecated를 한다.
3. Latest 문법은 깔끔하다.

꼭 언어에만 한정된건 아니다. 예를 들자면 C++은 1번을 잘했지만, 2번과 3번을 못하고, Java와 Windows도 그렇다. 하지만 2,3번을 잘하는 경우에는 1번을 잘 못한다. 파이썬이 2버전에서 3버전이 될 때에도 그랬고, node.js 기반 많은 웹 프론트엔드 프레임워크들도 그랬다.

유일하게 전부 다 잘한 경우가 있는데, 그 경우가 리눅스 생태계와 HTML, C언어다. 리눅스 생태계는 이 문제를 "하위 호환을 버리며 개발한 뒤, 하위 호환은 호환 계층으로 한다."같은 방식으로 해결했다.[^1] 모듈식 운영체제라 가능한 일이다. HTML은 많은 문법을 Deprecated시키면서도 Deprecated된 문법들도 구현해놓는 식으로 해결했다. 따라서 브라우저 엔진은 복잡해졌지만 문법 자체는 그렇게 복잡해지진 않았다. C언어는 애초에 기능 자체가 많지 않아서 추가할 기능도, Deprecated시킬 기능도 없었다. 아무리 운영체제가 현대화 되어도 C언어는 지금 그대로 잘 작동한다. 어셈블리랑 밀접한 언어이기 때문이다.

"모던 테크스럽다"에 대한 이야기를 해보자. 모던 테크스럽다는 게 뭘까? 정확히 설명하기는 어렵지만 나는 대부분의 모던 테크 기술 스택에서 "엘리트 주의"가 싫었다. 프로그래밍 언어의 얘기를 해보자면 엘리트 주의는 보통 이런 형식이다.

1. 포메터 내장
2. 사용 방법 강제
3. 디렉터리 구조 강제[^2]
4. 소스코드 파일 외에 언어가 작동되기 위한 필수 파일들이 존재
5. 내장 패키지 매니저가 너무 강력함[^3]

이것 외에도 다른 점들도 많겠지만, 내가 제일 싫어하는 건 보통 이런 요소들이다. 특히 4번, 너무 싫다. C언어는 `main.c` 만들고 그냥 `gcc main.c` 하면 돌아간다. Golang같은 언어는 `go mod init`이니 뭐니 정말 머리가 아프다.

내가 좋아하는 언어를 순위를 매겨보자면 이렇다.

1위 Python C언어 
2위 Java Kotlin  
3위 C++[^4]  
4위 Golang[^5]  
53,792,829위 Rust

러스트가 저렇게 낮은 이유는 **문법도 안 이쁜데다가 모던 테크스럽기까지 하다.** 게다가 뭐만 하면 러스트.. 러스트... 자꾸 잘만 쓰고있던 프로그램을 러스트로 Rewrite하질 않나, 그냥 내 눈앞에서 꺼졌으면 좋겠는데 자꾸 눈앞에 나타나면서 비호감 스택까지 쌓고있으니 좋아할수가 없다. 물론 저 언어가 좋다고 생각하긴 한다. 문법이 안 이쁘고 모던 테크스럽다는 점 빼면 완벽한 C++의 대체재이기 때문이다.

자바 코틀린은 정말 완벽한 C++의 대체재이다. 문법도 자바야 장황하고 별로지만 코틀린은 정말 이쁜 편이다. 생태계도 넓고, 다 좋은데 성능이 C++만큼 안 좋고 VM 언어이며 이세상의 모든 모던 테크 기술들의 시초가 자바이다. 난 저게 너무 싫다. 디렉터리 구조 강제는 물론이고 필수 파일들도 많고 인텔리제이가 아니면 자바를 쓰는게 불가능할 정도다. 솔직히 자바정도는 워크플로우가 익숙하기 때문에 쓰라면 쓸수 있다. 하지만 나는 그렇게까지 자바를 쓰고싶지는 않다. 쓰라면 C++을 쓰고말지.

아무튼, 이 글은 여기서 끝이다. 어떻게 끝내야 할지 잘 모르겠다. 나는 요즘 기술이 싫다. 솔직히 말하자면 요즘에 태어나서 편한거 많이 경험했으니까 과거로 돌아가서 핸드폰 없이 살라고 하면 불편한 것이지 처음부터 과거에 태어나서 요즘 편한거 경험 못하고 살았다면 나는 훨신 좋았을 것 같다. 물론 요즘에 태어나서 옛날의 좋은 점만 보고 살았으니 이런 말을 하는거고 막상 과거에 태어났어도 불평불만하며 살았을거 뻔하지만 아무튼 그렇다. 나는 모던 테크를 싫어하지 않는다. 각주를 다 읽었다면 알 테지만 난 웹 생태계를 정말 좋아한다. (물론 파이썬만큼 좋아하는 건 아니다.) 그리고 나는 uv(파이썬 패키지 매니저)도 좋아하고 잘 쓰고있다. ~~다만 저것도 러스트로 만들어져서 가끔 짜증나긴 한다.~~ 모던 테크 소프트웨어중에 좋은것도 정말 많다. 솔직히 이성적으로만 본다면 모던 테크는 정말 완벽하다. 근데 이 세상에 기술 스택이나 물건을 고를 때 꼭 이성적 판단으로만 고르는 경우는 거의 없다. 아니, 없다. 아무리 물건이 좋아도 감정적으로 끌리지 않는다면 그건 꽝이다. 물론 아무리 물건이 꽝이여도 감정적으로만 좋으면 그걸 써야한다는 건 아니지만 나는 살면서 어떤것을 고를 때 이성적인 사고보다는 감정적인 판단이 앞서는 편이다. 프로그래밍 언어도 그건 마찬가지다.

[^1]: 정확히 말하자면 리눅스 커널의 이야기는 아니다. 리눅스 커널 위에서 돌아가는 데스크톱 앱 등이 저렇게 했다. 예시로 X11에서 Wayland로 넘어갈 때 생겼던 XWayland라던지.
[^2]: 정확히 말하자면 이건 **프레임워크**에도 해당되는 이야기다. 나는 프레임워크도 싫다. 다른 글에서 다시 다룰수 있겠지만 간략히 말해보자면 나에게 친숙한 워크플로우와 프레임워크에서 강제하는 워크플로우가 다른 경우가 매우 많기 때문이다. 잘 맞는 경우는 SvelteKit, Astro 등이 있고, 잘 안 맞는 경우는 Unity나 Django, 아니면 Qt, GTK같은 Retained Mode UI 프레임워크가 있다.
[^3]: 파이썬 등은 패키지를 운영체제에 설치하지만, 모던 테크 패키지 매니저는 프로젝트마다 분리해서 설치하는 편이다. uv나 pnpm같이 잘 만들어져서 편하고 좋은 경우도 있지만, Golang같은 경우에는 내장 패키지 매니저 때문에 4번에 해당하게 되어 싫다. 생각해보면 전체적으로 모던 테크 웹은 잘 받아들이지만 그 외의 경우에는 잘 못 받아들이는 것 같다.
